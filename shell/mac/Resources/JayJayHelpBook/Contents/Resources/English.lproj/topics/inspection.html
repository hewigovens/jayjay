Inspection

Inspect file history and evolog

JayJay includes inspection tools for understanding where code came from and how rewritten changes evolved.

  • File Annotate shows blame information and lets you navigate to the responsible change.
  • File History opens in a separate window and lists revisions that modified the selected file, with the selected revision’s diff alongside it. Choose Pin as Base, then select another revision to compare the file between them. Swap reverses the endpoints; Clear or Esc clears the base. Right-click a revision and choose Show in Graph, or double-click it, to reveal it in the repository window.
  • Find a regression with Bisect… in the command palette, Bisect from here… in a change’s context menu, or Bisect between on two selected changes. Set Good and Bad endpoints, or enter a revset Range to use as-is, then choose Start. JayJay checks out candidates and highlights the search in the graph; mark each one Good, Bad, or Skip in the bar under the toolbar.
  • The bisect bar’s Run Test… control runs a shell command for this step or to the end. Exit status 0 means Good, 125 means Skip, 127 aborts, and other failures mean Bad. The bar shows command output and the result; its close button stops bisecting and restores the original working copy, reporting any temporary changes it kept.
  • Change Evolution shows prior versions of a rewritten change. Consecutive working-copy snapshots collapse into one row, Hide snapshots removes them entirely, and selecting two versions compares them directly. Right-click a version to Restore this version into the working copy or the change you opened the evolog for, in one undoable operation, or to copy its commit id or a jj restore command; immutable changes cannot be restored.

Pin a base and choose another revision to compare the file between them.

Bisect checks out a candidate and keeps Good, Bad, Skip, and Run Test close to the graph.

Change Evolution makes rewritten snapshots visible without digging through the operation log by hand.
