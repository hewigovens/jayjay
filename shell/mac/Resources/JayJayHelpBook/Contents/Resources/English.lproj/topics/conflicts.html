Conflicts

Resolve conflicts

Select a conflicted, mutable change in the graph, then a conflicted file in its file list. The conflict banner above the diff contains the whole-file choices and Edit in JayJay action. Review its sides before choosing a resolution.

  • Use inline Use Ours or Use Theirs when the file can be resolved that way.
  • Use Edit in JayJay to open a large, syntax-highlighted modal over the current detail. Two-sided conflicts show Base-relative Left and Right sources on top and each conflict once as a unified Left-to-Right diff below. Quiet Accept Left, Accept Right, and Accept Base links include hover help; -/+ stay in a non-editable gutter, and Option-Left or Option-Right applies to the selected hunk. Source and result panes scroll together, with the pane you scroll leading the others. Switch Result to Raw for direct, soft-wrapping marker editing. N-way jj conflicts remain editable through their markers, and partial resolutions can be saved while markers remain.
  • Choose Save Resolution to write the resolved result and close the editor. If markers remain, Save Partial Resolution saves the work while keeping the file conflicted. Cancel or Esc closes the editor without saving its edits.
  • Open the conflict banner’s resolution menu. It offers the merge editor configured by jj’s ui.merge-editor, Edit in JayJay for supported text conflicts, and the external Editor selected in Settings > Integrations > Applications. Choose Resolve in <tool> to hand the file to a merge tool, or Open in <editor> to open the working-copy file when that editor has no merge-tool integration. Complete and save the resolution there, then return to JayJay.
  • JayJay refreshes after resolution so the graph and file list reflect the new state.

For direct CLI use, first install the bundled jayjay launcher from Settings > Integrations > Version control and ensure ~/.local/bin is on your PATH; see tools and settings. Run jayjay config for the paste-ready tool definition, or choose Copy Config beside jj tool configuration on that settings page. Paste it into your jj user config file; jj config path --user prints its path.

Then run jj -R /path/to/repo diff --tool jayjay for a read-only comparison, jj -R /path/to/repo split --tool jayjay for interactive diff editing, or jj -R /path/to/repo resolve --tool jayjay path/to/conflicted-file for conflict resolution. jj edit selects the working-copy revision and does not accept a diff tool.

External diff session headers remain visible while you scroll. Diff and merge load failures show a readable error. Run jayjay tool --help to see usage without opening a session.

For Git, configure the same app as a custom diff and merge tool:

[diff]
    tool = jayjay
[difftool "jayjay"]
    cmd = jayjay tool diff "$LOCAL" "$REMOTE"
    prompt = false
    trustExitCode = true
[merge]
    tool = jayjay
[mergetool "jayjay"]
    cmd = jayjay tool merge "$LOCAL" "$BASE" "$REMOTE" "$MERGED"
    trustExitCode = true

Then run git difftool --dir-diff or git mergetool.

Resolve each conflict with Accept Left, Accept Right, or Accept Base; save a partial resolution when work remains.
