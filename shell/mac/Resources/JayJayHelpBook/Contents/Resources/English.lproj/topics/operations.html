Changes

Operate on changes

Open a repository and select a change in its history sidebar. Right-click that row for change actions, or press Cmd+Shift+P and search for an action in the command palette. Rewriting requires a mutable change; see the core concepts for the working copy, parents, and protected history.

  • For the working copy @, enter a Summary and optional Description in the commit box below the graph. Describe saves that message to the current change; Commit saves it and starts a new empty working-copy change on top. File edits are already part of @, so no staging is needed. The box starts with the current description and preserves a typed draft when @ moves to an empty change. The description dialog uses the same Summary and Description fields, keeps that draft, and leaves unchanged formatting and indented bodies as they are.
  • The change’s context menu offers New change on top, New change before, and New change after when its topology permits them. Rebase onto trunk moves the whole line of work, including a workspace's working copy; Rebase Working Copy onto Trunk in the command palette does the same for @.
  • Edit (modify this change) moves the working copy to the selected mutable change. Squash into parent moves its edits into its parent. Under More Actions, Duplicate copies a change, Absorb into ancestors distributes its edits into ancestors, and Revert change creates a new change that reverses its edits. Abandon removes the selected change from the visible history.
  • Shift-click changes to select a batch, then merge independent heads, squash a consecutive linear range, parallelize a connected run into siblings, abandon mutable selections, or rebase them onto another row while preserving their dependencies.
  • Run formatters (jj fix) on a change, a selection, or from the command palette runs the tools in your [fix.tools] config over those changes and their descendants. A failing tool leaves its file unchanged and is reported, and an unusable config disables the items with the reason.
  • Create a lightweight tag from a change's context menu. A tag chip's menu pushes a local-only tag, copies its name, or deletes it; Delete Tag on Remote removes the tag locally and from every remote that tracks it, restoring the local tag if the push fails.
  • Right-click selected files in the file list for Split to New Change, Move to Working Copy on historical changes, or Delete from Disk on the working copy. See Split work for file and line selection steps.
  • The sparkles button beside Describe generates a message through an available Codex CLI, Claude CLI, or Apple Intelligence provider. Review the generated Summary and Description before choosing Describe or Commit. Drag providers in Settings > Integrations to choose their fallback order.
  • Choose Repository > Undo Last Operation or press Cmd+Shift+U to open the operation log. Select an earlier operation and choose Restore to return the local repository to that state; the current operation cannot be restored. Cancel closes the log without restoring. This restores repository history and working-copy state, not published remote changes or local review marks and notes.
