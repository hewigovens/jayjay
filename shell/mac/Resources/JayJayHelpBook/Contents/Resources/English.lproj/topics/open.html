Getting started

Open a repository

Choose File > Open Repository... or press Cmd+O, then select a jj workspace or a folder inside it. JayJay opens the enclosing workspace. The CLI launcher also accepts subfolders, so jayjay . works from a nested source directory.

The history sidebar lists changes. Select a change to populate the file list, then select a file to read its diff. The @ row is this workspace's working copy; see the core concepts for jj terminology.

  • To open repositories from a terminal, choose JayJay > Settings… > Integrations and click Install beside jayjay. This links the bundled CLI at ~/.local/bin/jayjay. Add ~/.local/bin to your shell’s PATH, then run jayjay /path/to/repo or jayjay .; you can also invoke ~/.local/bin/jayjay . directly.
  • Choose Clone… on the welcome screen or File > Clone Repository… to clone a Git repository into a new jj checkout. Paste its URL, adjust the suggested name and location, and choose Clone. Cancel stops an in-flight clone; the repository opens when it finishes.
  • To work on a repository on another machine, choose File > Open Remote Repository…. Pick or type an SSH host or config alias, browse to the repository folder, and choose Connect; a folder without a repository offers jj git init. The host must accept key or agent authentication without a prompt and already be in known_hosts. macOS, Linux, and Windows hosts are supported: on first connect JayJay downloads the small helper it runs on the host and checks it against this release. Click the host in the status bar to disconnect or reconnect. While disconnected the repository stays on screen and JayJay never retries a write on its own, so reconnect and refresh before trying again. Review notes stay on this Mac, and Finder, editor, and terminal actions are unavailable for remote repositories.
  • Onboarding offers Set Up… when your jj author identity is missing. Enter the name and email that jj should record on new changes, or set them later in Settings > Jujutsu.
  • The Repository List separates persistent Pinned repositories from Recent Repositories and groups recent sibling-workspace checkouts beneath their primary repository. Use the pin button to keep a repository in the list; clearing Recent does not remove pins, and unpinning returns a repository to Recent. Recent Repositories sit in a side panel that opens with your first recent repository, closes when the last one is removed, and toggles from the sidebar button in between. Drag its divider to size the panel; the width persists across launches, and workspace rows show their path under the name.
  • Click the repository title to search this repository's workspaces, other open windows, pinned repositories, and recent repositories, or return to the full Repository List. Use Overview in the picker to open the Repo Overview, and a row's context menu to pin or unpin that repository or workspace.
  • Right-click a workspace row in the title picker, or its name@ graph chip, and choose Filter by This Workspace to narrow the graph without switching checkouts. Clear the revset filter to restore the default view. Choose Repository > Show in Finder, press Option-Command-F, or use the folder toolbar button to reveal the current checkout.
  • Choosing a workspace in the title picker, or a command-palette Switch to entry, opens it in the current window, or brings its window forward if it is already open. The window keeps showing the source workspace, with the refresh indicator spinning, until the destination has loaded; if it fails to open, the source stays usable and JayJay shows the error. Unsaved commit-message drafts are kept per workspace. Option-click a workspace or choose Open in New Window from its context menu for a separate window.
  • To create a workspace, choose Repository > New Workspace… or find New Workspace in the command palette. Enter a workspace name and choose Create. JayJay creates a sibling directory with that name beside the current checkout and opens the new workspace. Cancel closes the sheet without creating it.
  • To check out a GitHub pull request or GitLab merge request, choose Repository > New Workspace from Pull Request…: paste its URL and choose Resolve. Review the repository, bookmark, and destination in the preview, adjust the workspace name if needed, then choose Fetch & Create Workspace. JayJay fetches the head and opens the new checkout; if it already exists, choose Open Workspace instead. GitLab uses GITLAB_TOKEN when available, then an existing glab auth login; public merge requests work without sign-in. A workspace row can open or copy the workspace name or checkout path, forget only the jj workspace metadata, or safely forget and delete the checkout after confirmation.
  • Repository > Repo Overview (Cmd+Shift+O) shows every lane of mutable work as a tree growing from trunk. Each lane card shows its workspaces and bookmarks and either its change count or what needs attention. Click a lane for its base, a Rebase onto trunk button when it is behind, its workspaces, bookmarks, and changes; click a change for its description and changed files, which you can select and copy. Filter lanes with Cmd+F, move with the arrow keys, press Return to show the selection in its workspace window, press Esc to step back out of a panel, and use the context menu to rebase a lane onto trunk, abandon it, or forget a workspace.
  • When another workspace rewrites this workspace's working-copy change, the working copy is stale: the @ row shows a warning glyph and the Refresh button a badge, and Refresh or Update Workspace in the row's menu updates it like jj workspace update-stale.
  • JayJay watches the repository and working tree and refreshes visible working-copy details after external changes. A refresh waits while an editor, review-note composer, or confirmation sheet holds unfinished input.
  • Hide or show the history sidebar with the toolbar button, View menu, or Control-Command-S. Onboarding, the Repository List, and each repository open in their own windows. Closing the last repository window returns to the Repository List automatically, and every window kind remembers its position and size across launches, as do the sidebar and file-column widths.
  • Recent repositories and Repository List… also appear in the Dock menu. Pinned repositories are shared with JayJay's GPUI shell, while each shell keeps its own recent history.
  • If the folder has no jj repository, the open-error screen offers Initialize with jj git init. Choose it to initialize that folder, then JayJay loads the repository.

After opening a repository, JayJay shows the DAG, changed files, and selected diff in one window.
