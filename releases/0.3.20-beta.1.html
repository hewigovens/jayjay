Repo Overview

  • Choose Repo Overview from the Repository menu, Cmd+Shift+O, the command palette, or the Overview button in the workspace picker to see every lane of mutable work as a tree growing from trunk. Each lane lists its changes, the workspaces checked out in it and how far below the head they sit, and notes for conflicts, undescribed changes, and an empty undescribed checkout above finished work.
  • Filter lanes with Cmd+F, move between lanes and changes with the arrow keys, and press Return to show the selection in its workspace window. The context menu rebases a lane onto trunk, abandons a lane or change, copies ids, opens or forgets a workspace, and reveals it in Finder.

Rebase and restore

  • Rebase onto trunk in a change's context menu, or Rebase Working Copy onto Trunk in the command palette, moves that whole line of work onto trunk, including a workspace's working copy. A rebase that moves nothing records no operation.
  • Dragging a change in the graph rebases again, and rows redraw after the rebase. Dragging one change of a multi-selection rebases the whole selection and reports conflicts in any moved change.
  • Restore this version in Change Evolution puts that version's content back into the working copy or the change you opened the evolog for, in one undoable operation. Immutable changes cannot be restored, and Copy ‘jj restore’ command now names the target change.

Repository List

  • Drag the Recent panel to the width you want. The panel keeps that width and the list keeps its window size across launches, and the panel no longer clips when it is wider than the window allows. Workspace rows show their path under the name.

Faster and steadier

  • Almost every repository action now runs in-process through jj-lib instead of spawning the jj binary: commit, describe, squash, split, revert, absorb, restore, untrack, bookmarks, workspaces, git import, the operation log, and undo. Only fetch, push, external merge tools, and raw palette commands still run jj.
  • Actions from different windows and workspaces of one repository run one at a time, so overlapping operations no longer leave a change divergent.
  • Undo records pending working-copy edits before it lists operations, so rolling back an operation cannot discard work typed after it.
  • Colocated Git repositories see the updated HEAD, branches, and newly tracked files right after each action instead of after the next jj command.
  • Settings > Jujutsu reads your config files directly, so it works without jj on the PATH, groups values by section, and names the file that failed to load with an Open action.
  • The alert for a missing user.name or user.email now appears when jj has no identity configured; it never fired before.
  • Absorb with nothing to move reports Unchanged instead of recording an operation, and the status bar and operation log shorten embedded operation and commit ids.
