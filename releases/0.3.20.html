Repo Overview

  • Choose Repo Overview from the Repository menu, Cmd+Shift+O, the command palette, or the Overview button in the workspace picker to see every lane of mutable work as a tree growing from trunk. Lane cards show their workspaces and bookmarks, the change count and age, and what needs attention: conflicts, undescribed changes, or an empty checkout above finished work.
  • Click a lane to open its panel with the base, a Rebase onto trunk button when it is behind, its workspaces with an Open button, its bookmarks, and every change with its full title. Filter lanes with Cmd+F, move with the arrow keys, and press Return to show the selection in its workspace window; the context menu rebases or abandons a lane, copies ids, and opens, reveals, or forgets a workspace.
  • Only the visible part of the canvas is built, so an overview with thousands of changes opens and changes selection in milliseconds.

Revset bar

  • The revset filter lives in the center of the title bar, quiet on the default Revset and tinted once the graph is narrowed. Click it, choose Repository > Filter by Revset… (Cmd+L), or use the command palette; the filter icon opens presets such as Bookmarks and Tags, the current revset, matching bookmarks, and this window's recent revsets.
  • As you type, the bar completes revset functions, your aliases, and bookmark, remote, and tag names at the caret. Tab or Return finishes the highlighted completion, and jj's parse error shows before the graph reloads.
  • The Bookmarks picker sits in the graph header beside the change count. Clicking a bookmark selects its change, or narrows the graph to the bookmark and its changes over trunk when it is not shown.

Workspaces

  • Choosing a workspace in the title picker or the palette's Switch to action opens it in the current window, or brings its window forward. The source stays visible until the destination has loaded, unsaved commit-message drafts survive switching away and back, and a workspace that fails to open leaves the source usable. Option-click or Open in New Window opens a separate window.
  • New Workspace from Pull Request… also takes a GitLab merge request URL, signing in through glab when it is installed, or a GITLAB_TOKEN otherwise.
  • When another workspace rewrites this workspace's working-copy change, JayJay no longer snapshots the old files over the rewrite. The @ row shows a warning glyph and the Refresh button a badge; Refresh, or Update Workspace in the row's menu, updates the working copy like jj workspace update-stale.

Changes

  • Rebase onto trunk in a change's menu, or Rebase Working Copy onto Trunk in the palette, moves a whole line of work onto trunk. Dragging one change of a multi-selection rebases the whole selection.
  • Select a connected run of changes and choose Parallelize to turn the stack into siblings. Merge N selected has a First parent submenu to choose which change leads the merge.
  • Run formatters (jj fix) on a change, a multi-selection, or from the palette runs the tools in your [fix.tools] config over the selected changes and their descendants with jj's semantics, including the newer line-range-args list. A failing tool leaves its file unchanged and is reported.
  • Create a lightweight tag from a change's menu. The tag chip offers Push while the tag is local only, and Delete Tag on Remote once a tracked remote has it, restoring the local tag if the push fails.
  • Restore this version in Change Evolution puts that version's content back into the working copy or the change you opened, in one undoable operation.

Diff and detail

  • The diff header shows the file's status pill and line counts next to its name, with Preview, the layout toggle, Edit Diff, and Edit File in one style on the right. The file column header puts its controls first and one count last.
  • Large diffs open and switch much faster: replacing a 6,000-line diff drops from over a second to a few milliseconds, and line wrapping is about ten times faster.
  • Fish scripts get syntax highlighting, and symbols such as ↩ draw as text in your code font instead of as color emoji.

Keyboard

  • h and l work like Left and Right, alongside j and k: Right in the graph moves to the file list and Left moves back. Keys nothing handles no longer beep.
  • The Keyboard Shortcuts window (Cmd+/) lists every shortcut, including Filter by Revset, Repo Overview, and the conflict editor's Option-arrow keys.

Faster and steadier

  • Almost every repository action runs in-process through jj-lib, now 0.46, instead of spawning jj; only fetch, push, external merge tools, and raw palette commands still run the binary. Actions from different windows of one repository run one at a time, so overlapping operations no longer leave a change divergent.
  • Undo records pending working-copy edits before it lists operations, and colocated Git repositories see the updated HEAD and branches right after each action.
  • Refreshing the graph after a snapshot is about four times faster in repositories with thousands of changes and hundreds of bookmarks.
  • Settings > Jujutsu reads your config files directly, so it works without jj on the PATH, and names the file that failed to load.

Fixes

  • Fixed a crash that could happen when a repository window closed while files in it were changing.
  • After a fetch or pull, a bookmark whose remote branch was deleted once its pull request merged is cleaned up in one undoable operation; unmerged and conflicted work is kept.
  • Show in Graph and Show ancestors… keep following a change after it is rewritten.
  • The commit box's Summary field keeps the caret where you put it, and the tree file list no longer jumps after a fast scroll.
  • The bookmark picker shows Loading bookmarks… on large repositories instead of opening empty, and panes waiting for content share one loading indicator.
  • Commits by coding agents such as Claude Code and GitHub Copilot show the account's GitHub avatar.
  • The missing user.name or user.email alert now appears when jj has no identity configured, and the file tree shows both entries when a file is replaced by a directory of the same path.
  • The sponsor prompt is now a rating prompt that offers Star on GitHub first; people who turned the old prompt off stay opted out.
