Find the first bad change

  • Use Bisect… in the command palette, Bisect from here… on a change, or Bisect between on two selected changes to narrow down a regression. Set good and bad endpoints or enter a revset range, then mark each candidate Good, Bad, or Skip.
  • The bisect bar follows your progress in the graph. Run a test command for one step or to the end, inspect its output, and stop the search to return to your original working copy.

Clone and get started

  • Clone a Git repository from the welcome screen or File → Clone Repository…. Paste the URL, choose a name and location, and open the new jj repository when cloning finishes. Cloning can be canceled.
  • Set your jj author name and email during onboarding, or edit them later in Settings → Jujutsu. An unset identity now appears as unknown instead of being shown as an extra co-author.

Compare file history and submit Codeberg stacks

  • File History now opens in its own window with a diff for the selected revision. Choose Pin as Base and another revision to compare the file between them, swap the endpoints, or use Show in Graph to reveal a change.
  • Create and update stacked pull requests on Codeberg, with dependent bases and stack links in each description. Set CODEBERG_TOKEN or FORGEJO_TOKEN with repository write access before submitting.

Fixes

  • Empty changes keep the file column visible, and a list with every file hidden explains why it is empty.
  • Colocated Git index updates now take the index lock before reading and writing, protecting concurrent Git operations.
