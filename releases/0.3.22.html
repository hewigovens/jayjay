History navigation

  • Follow the selected graph lane with j/k, Up/Down, or Ctrl-N/P, and switch columns with h/l or Left/Right. Tab and Shift-Tab move between panes. The selected lane stands out while other graph lines fade, even while the file list has focus.
  • Stacks stay together with the working copy’s stack first, and row dates use the committer time so rebased work shows its latest rewrite.
  • The default graph filter follows your jj revsets.log setting. Default, Reset Filter, and an empty revset return to it.
  • Recent revsets are saved per repository, shared by all its workspaces, and kept after the window closes, up to 15; each can be removed from the revset panel. Workspace names complete as name@, and graph bookmark chips, workspace chips, and workspace picker rows offer Filter by This Bookmark or Filter by This Workspace.
  • Press Control-Return in the graph or file list to open the selected change or file’s context menu from the keyboard. Search for Show Evolution in the command palette to inspect the selected change’s rewrite history.

Find the first bad change

  • Use Bisect… in the command palette, Bisect from here… on a change, or Bisect between on two selected changes. Mark each candidate Good, Bad, or Skip, or run a test command for one step or to the end; the bisect bar follows your progress in the graph.

Diffs and review

  • Unified and side-by-side diffs link code that moved between hunks. Click a line-number badge to jump to the matching block.
  • Two selected revisions compare their endpoint trees when they cannot form a combined diff, including sibling changes and merges.
  • Renames come from jj’s copy records, so a new file is no longer shown as a move of an unrelated file with the same name. Copies show as Copied and diff against their source.
  • File lists and diff headers show file-type and language icons, status badges use clearer symbols, and binary sizes follow your locale with exact byte counts on hover. The file list keeps the selected file in view while you move through it.
  • Right-click a line number in either diff layout to edit the working-copy file at that line in the built-in editor or a supported external editor.
  • Markdown previews render fenced Mermaid blocks as diagrams offline and support pinch zoom; unsupported or oversized diagrams stay readable as source.
  • Copying text from side-by-side diffs preserves the original source lines, joining soft-wrapped rows and leaving out alignment padding.
  • Syntax highlighting adds PowerShell, Batch, INI, CMake, XML-family, and Fluent files, and TypeScript and TSX files again color keywords, strings, comments, and JSX markup.
  • File History opens in its own window. Choose Pin as Base and another revision to compare the file between them.

Colors, fonts, and language

  • Choose separate light and dark diff palettes in Settings → Appearance, including Catppuccin, Dracula, Gruvbox, Nord, One, Solarized, and Tokyo Night; the palette also colors editors and syntax highlighting.
  • A Fonts page sets the interface and code font families and sizes, code line spacing, and ligatures, with a live preview. The code font picker lists coding fonts first, including Nerd Font patches, and changing fonts keeps the diff on the same line.
  • Choose System, English, Japanese, Simplified Chinese, or Traditional Chinese in Settings → Appearance. Most text updates immediately; use Relaunch to update macOS system menus and update dialogs.

Clone, sign in, and publish

  • Clone a Git repository from the welcome screen or File → Clone Repository…, and set your jj author name and email during onboarding or in Settings → Jujutsu.
  • Sign in to GitHub and GitLab from Settings → Integrations with a browser code. GitHub and GitLab operations call their APIs directly, so existing gh/glab logins and environment tokens work without either CLI.
  • Create and update stacked pull requests on Codeberg with CODEBERG_TOKEN, FORGEJO_TOKEN, or a tea login. Cursor Origin pull requests and stacks use its API with your Origin login.

Integrations and diagnostics

  • Turn on Integrate with coding agents in Settings → Integrations to install the JayJay skill for Claude Code, Codex, and Cursor, so they can work with your review notes and marks.
  • Choose Rex in Settings → Integrations to open repository folders in Rex. The conflict banner offers your jj-configured merge editor alongside Edit in JayJay and your external editor.
  • Open the current repository in Finder from the toolbar, Repository menu, or Option-Command-F. Opening a subfolder opens its enclosing jj workspace, including through the CLI launcher.
  • Help → Reveal Logs shows the local log. Debug mode in Settings → Data & Privacy records extra snapshot and graph timings, and Send Feedback can attach the log for you to review before sending.

Fixes

  • The change header credits co-authors from description trailers and a distinct committer.
  • Forgetting a Git-backed workspace releases its Git worktree registration so the path can be reused.
  • Large files with many scattered edits no longer overflow the diff engine’s stack, and tabs count as four cells when wrapping and selecting diff text.
  • Creating a bookmark or tag with a name git can’t store is refused up front, and comparing against a bookmark that exists only on a remote works again.
  • Git LFS files with spaces or non-ASCII names are recognized, colocated Git index updates take the index lock, and review marks and notes saved by the app and the jayjay CLI at the same moment no longer overwrite each other.
  • Clicking the Dock icon restores a minimized repository window, empty changes keep the file column visible, and no usage statistics are sent before onboarding finishes.
  • Updated dependencies include security and compatibility fixes.
