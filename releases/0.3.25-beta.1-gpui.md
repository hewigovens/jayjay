## Operation Log

- The Operation Log opens as a resizable pane at the window's trailing edge instead of a separate window. Show or hide it with its toolbar button, **View → Show Operation Log** (Ctrl+Shift+U), the last operation in the status bar, or the command palette. JayJay remembers whether it is open.
- In a narrow window the pane gives up width before the sidebar, file list and preview do, and hides once it cannot keep its own minimum; widening the window restores the width you dragged it to. Showing it in a window that is too narrow says so, and the pane appears once there is room.
- Restore an operation from its row's context menu, Ctrl+Return, or **Edit → Restore Selected Operation**. A refresh keeps the selected operation.
- When the operation history cannot be read, the pane shows the error instead of an empty list. When the revset stops evaluating, the pane still shows the operation that broke it.

## Toolbar and layout

- The sidebar and the Operation Log are full-height columns, and the toolbar spans the space between them. Refresh, pull and push sit at the top of the sidebar column and leave with it, while the sidebar and Operation Log toggles stay at the window's leading and trailing corners. Both panes slide open and closed, without animation when reduced motion is on.
- Pull and push use a matching pair of tray icons, and review mode uses a checklist icon so it no longer looks like a reviewed file's mark.
- The toolbar no longer has Settings or file manager buttons; both remain in the menus and the command palette. Editor and terminal buttons show the configured app's icon.
- Double-clicking a toolbar button no longer maximizes the window; double-clicking empty toolbar space still does. Clicking a toolbar button leaves keyboard focus where it was.
- The repository title is larger and lines up with the change title, following the sidebar toggle when the sidebar is hidden.
- The change header, with its title, description, byline and stats and the compare, divergence and stale-note bars, now spans the file list and the diff. Details stay collapsed by default.
- The sidebar and Operation Log use a side-panel surface with their own hover and divider colors, while the file list, diff and change header stay on the content background. Toolbar buttons have a clearer hover, the revset field is centred on the window, and a dark selection stays visible on the side panels.
- The change description uses the interface font and shows two lines while collapsed, and the copy buttons beside IDs and paths are smaller.
- **View → Hide Status Bar** and **Hide / Show Status Bar** in the command palette hide the status bar.
- Context menus near the window's trailing edge open leftward from the pointer, and menus size to their labels at the current zoom.
- Tooltips wait a second before appearing and no longer show over an open context menu. A menu row still explains why it is disabled.

## Changes and commits

- The commit box in the sidebar appears only while the working copy has no description or holds an unsaved draft.
- A described working copy has **Edit** in its change header. The sheet offers **Commit** and message generation besides saving, and stays open if the commit fails.
- A described working copy's change menu offers **Commit**, which commits an unsaved draft that has a summary, or otherwise the saved description.
- The change header shows the commit ID beside the change ID, each with its unique prefix highlighted and a copy button. In a narrow pane the date drops first, then the commit ID.
- The change list header shows how many changes are divergent or conflicted, moved from the status bar. Click a count to filter to `divergent()` or `conflicts()`.
- Change ID prefixes and bookmarks are magenta and commit ID prefixes are blue, as in `jj log`.

## Files and diffs

- File rows show the containing folder under the file name, in the flat list and the tree alike. Files at the repository root have no second line, and moves still show their full source and destination.
- An empty change shows **No Files Changed** once across the detail pane, with the file list hidden until the change has files.
- When a change has files but none are listed, the diff area says why — no search match, all files reviewed and hidden, no files with review notes, or Git LFS and submodule files hidden by settings — and ends with a link that undoes it, such as **Clear Filter** or **Show Reviewed Files**.
- Page Up, Page Down, Home and End scroll the diff or Markdown preview while the change list or file list has the keyboard.
- Syntax colors stay distinct from one another in low-contrast themes.

## Review

- A mutable change other than the working copy has its own review mode, turned on from the toggle after Search in the file list header, **Repository → Review Mode**, or **Toggle Review Mode** in the command palette. It starts on when the change already has review marks or notes, and off otherwise.
- With review mode off, file rows show the change-type badge instead of review marks, the diff header has no **Mark Reviewed**, Space does not mark, and hiding reviewed files and the reviewed count are off. Review notes still show.

## Git submodules

- **Enable Git submodule support** in Workflow settings is now **Show Git submodule changes** under **Git LFS and Submodules** in Diff settings, since it only controls whether submodule changes are listed. Your existing choice carries over.
- A submodule's diff says that JayJay shows only which commit it points to.

## Pull, push and remote repositories

- A failed pull shows Git's own output instead of only "External git program failed".
- Push says plainly when there is nothing to push, for example when no bookmark is ahead of the remote.
- A disconnected SSH repository shows a bar with **Reconnect** above its content. **Reconnect** is also in the Repository menu and the command palette.
- On Windows, jj and gh can start Git installed through a Scoop shim when a launcher such as PowerToys Run starts JayJay.
