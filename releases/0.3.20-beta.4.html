Workspaces from merge requests

  • New Workspace from Pull Request… now takes a GitLab merge request URL too. JayJay resolves the merge request and its source project through the GitLab API, adds a fork as a remote when needed, fetches the head, and creates the sibling workspace. Sign-in goes through glab when it is installed; otherwise a GITLAB_TOKEN or a public merge request works without it.

Fix with jj's tools

  • Choose Run formatters (jj fix) on a change, on a multi-selection, or from the command palette to run the tools in your [fix.tools] config over the selected changes and their descendants, with jj's semantics for enabled, line-range-arg, and run-tool-if-zero-line-ranges. A failing tool leaves its file unchanged and is reported, an immutable change is refused before anything runs, and a run that changes nothing records no operation. An unusable config disables the menu items with the reason.

Merging

  • Merge N selected opens a First parent submenu so you choose which selected change leads the merge; the remaining parents keep their graph order.

Fixes

  • The commit box's Summary field keeps the caret where you put it: fast typing no longer scrambles characters, and typing after clicking into the middle of a long summary no longer jumps to the end.
  • In tree mode, selecting a file after a fast trackpad scroll no longer makes the file list jump away from the clicked row.
  • The sponsor prompt is now a rating prompt that offers Star on GitHub first, with Sponsor beside it. People who turned the old prompt off stay opted out.
  • Release builds are signed with the renewed Developer ID certificate; nothing changes for updates, but tell us if Gatekeeper complains on first launch.
